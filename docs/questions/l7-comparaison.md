# Questions — lot L7 (comparaison A/B, journée de référence, tableau de bord)

Aucune ne bloque : une valeur par défaut est adoptée, notée ici, et isolée dans le code pour être changée
facilement. Les définitions exactes des indicateurs sont dans la docstring de
`backend/app/comparison/metrics.py`.

## À trancher avec OLA

| # | Question | Valeur adoptée en attendant |
|---|---|---|
| L7-1 | Critère 2 (§13) : le « kilométrage du plan manuel » auquel on compare le plan calculé est-il son kilométrage **estimé** (recalculé sur la matrice du moteur) ou son kilométrage **réel** (compteur) ? | Verdict sur les km **estimés des deux plans**, même matrice (comparaison à armes égales). Le gain par rapport aux km réels de A est donné à titre d'information (`gain_vs_actual_pct`), seulement si toutes les tournées de A ont des km réels. |
| L7-2 | Q6 : que contient réellement la journée A d'OLA ? Y a-t-il les commandes **demandées** (y compris celles qui n'ont pas été livrées), ou seulement les tournées faites ? | Les deux cas sont acceptés : feuille « Commandes » facultative ; si elle est vide, les commandes sont déduites des tournées (demandé = livré) avec un avertissement. Km réels et heures : facultatifs, colonne par colonne. |
| L7-3 | Le fichier d'OLA donne-t-il la répartition par compartiment des tournées manuelles ? | Non prévu dans le modèle. Le plan de chargement du plan manuel est réparti par `assign_compartments` (lot L2), comme pour un plan calculé, et enregistré dans `trip_compartment_loads`. Si aucune répartition n'est possible, la tournée reste sans plan de chargement et les règles signalent RM-05 (bloquant) : le plan manuel est alors jugé infaisable sur ce point, ce qui peut être faux si le référentiel des compartiments est incomplet. |
| L7-4 | « Mêmes ressources » du rejeu (F8.2) : faut-il limiter le moteur aux camions et chauffeurs que le dispatcher a réellement utilisés, à ceux qui étaient disponibles ce jour-là, ou à toute la flotte ? | Le rejeu transmet les mêmes commandes ; les ressources sont celles que `build_problem` (lot L5) retient pour la date de la journée de référence. Pour un jour passé, la disponibilité de l'époque doit avoir été saisie (F2.2/F2.3), sinon la flotte actuelle est utilisée. `launch_compute` n'a pas de paramètre pour restreindre les ressources. |
| L7-5 | Le temps de préparation d'un plan **calculé** doit-il inclure le temps passé par le dispatcher à l'ajuster (journée B) ? | `prep_time_s` s'il est saisi, sinon `computed_in_ms` arrondi à la seconde. La spec ne prévoit pas de route pour saisir `prep_time_s` après coup : il n'est saisissable qu'à l'import de la journée de référence (formulaire ou feuille « Journée »). |
| L7-6 | Tableau de bord : quand une alerte cesse-t-elle d'être « active » ? La table `events` n'a pas d'état « traité ». | Toutes les violations du plan publié et tous les événements de panne, d'indisponibilité chauffeur et de pénurie du jour sont listés, du plus récent au plus ancien. Aucun seuil de retard n'est appliqué : tout arrêt arrivé après l'heure prévue figure dans `delays`. |

## Choix de réalisation (à valider à l'intégration)

| # | Constat | Décision provisoire |
|---|---|---|
| L7-7 | F8.4 « stations livrées / demandées », « volumes livrés / demandés » : livré = planifié ou réellement livré ? | Les deux sont exposés. `stations_served` / `volume_planned_l` : ce que le plan sert (comparable entre deux plans, c'est la valeur du tableau). `stations_delivered` / `volume_delivered_l` : réalisations saisies (F7.4), `null` tant que rien n'est réalisé. « Demandé » = commandes des livraisons du plan + commandes de `unserved_orders`. |
| L7-8 | Km réels renseignés sur une partie seulement des tournées. | `distance_actual_m` = somme des tournées renseignées, `distance_actual_trips` = nombre de tournées concernées. `null` si aucune. L'écart A/B n'est calculé que si les deux valeurs existent. |
| L7-9 | Taux de remplissage moyen : moyenne simple par tournée ou pondérée par la capacité ? Quel dénominateur ? | Moyenne simple, sur les tournées ayant au moins un arrêt, de (volume planifié ÷ somme des capacités des compartiments du camion, comme le service de plans ; à défaut `trucks.total_capacity_l`). La marge de sécurité RM-05 n'est pas déduite du dénominateur. |
| L7-10 | Tournées sans arrêt (vides). | Ignorées dans tous les indicateurs et sur les cartes. |
| L7-11 | Statuts à l'import d'une journée de référence. | La journée a eu lieu : tournées `completed`, arrêts `delivered`, `actual_l` = volume du fichier ; commandes livrées `delivered`, non livrées `postponed` et inscrites dans `unserved_orders` (raison `other`). Ces commandes sont créées par l'import (`source = import`, `import_batch_id`) : elles ne sont jamais `confirmed`, donc un calcul ordinaire lancé sur la même date ne les reprend pas. Le plan reste `draft` (jamais publié) pour rester visible dans les listes ; le lot L5 devrait refuser l'édition et la publication d'un plan `manual_reference`. |
| L7-12 | Heures prévues d'un plan manuel (nécessaires à RM-02/10/11). | Calculées par `schedule_trip`. Si l'heure réelle de départ du dépôt est connue, le calcul démarre à (départ réel − attente − chargement), borné par le début de journée ; sinon les tournées d'un même camion ou d'un même chauffeur s'enchaînent dans l'ordre du fichier. Les heures réelles sont stockées telles quelles dans les colonnes `actual_*`. |
| L7-13 | Réimport d'une journée déjà importée. | 409 par défaut. Avec `replace=true` : l'ancien plan de référence passe `archived`, ses commandes importées passent `cancelled`, un nouveau plan est créé. Les rejeux de l'ancien plan sont conservés. |
| L7-14 | Fichier contenant des erreurs. | Tout ou rien : lot `rejected`, rapport complet, aucune commande ni plan créé. Réponse 422 au format `{code, message, details[]}` enrichie du rapport. `dry_run=true` contrôle le fichier sans rien créer (lot `previewed`). |
| L7-15 | Une ligne par (station, produit) dans la feuille « Commandes ». | Doublon = erreur. Une commande peut être livrée en plusieurs fois (plusieurs tournées) ; volume livré > demandé = avertissement. Livraison sans commande alors que la feuille est remplie = avertissement et commande déduite. |
| L7-16 | Identification du chauffeur dans le fichier. | Numéro de permis, sinon nom complet (insensible à la casse et aux accents). Homonymes = erreur. Chauffeur absent = avertissement (tournée sans chauffeur), chauffeur inconnu = erreur. Produit : code ou libellé. |
| L7-17 | Plan publié du jour pour le tableau de bord, s'il y en a plusieurs. | Le plan `published` de version la plus haute (puis le plus récent). Sans plan publié : `plan = null`, seules les alertes issues des événements sont renvoyées. |
| L7-18 | Retard estimé d'une tournée. | Écart réel − prévu du dernier fait connu (départ dépôt, puis arrêts réalisés, puis retour dépôt) ; `null` sans heure réelle. L'arrivée estimée au prochain arrêt = heure prévue + retard constaté (jamais avancée). |
| L7-19 | Génération du PDF (§8.2 : Celery). | Rendu synchrone dans un fil d'exécution pendant la requête (le document tient en quelques pages). À déplacer en tâche de fond si les temps de réponse le demandent. |
| L7-20 | Taille maximale du fichier importé. | Paramètre `import_max_file_mb` du lot L3, appliqué aussi à `POST /reference-days/import` (413 au-delà). |
| L7-21 | Deux chemins d'import pour la journée de référence. | `POST /reference-days/import` (spec §9, une étape) et le cycle commun `POST /imports/reference_day/preview` → `POST /imports/{batch_id}/apply` (registre du lot L3) passent par les mêmes fonctions et produisent le même lot `import_batches`. Un contrôle seul (`dry_run`) de la première route peut être appliqué par la seconde. |
| L7-22 | Commande urgente non livrée lors de la journée de référence (RM-15). | À l'import, toutes les commandes non livrées sont soumises aux règles : une urgente non livrée donne une violation RM-15 bloquante sur le plan manuel. Un recontrôle ultérieur par le service de plans (`recheck_plan`) écarte, lui, les commandes `postponed` : la violation disparaîtrait. À harmoniser si un plan de référence doit pouvoir être recontrôlé. |
| L7-23 | Journée de référence passée par un dépôt désactivé depuis. | Refus 409 `reference_day_inconsistent` : `build_problem(order_ids=…)` ne retient que les dépôts actifs. Test `xfail` : `test_import_journee_passee_par_un_depot_desactive`. |
